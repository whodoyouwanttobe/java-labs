# Лабораторная работа 2. Собственные структуры данных, асинхронность

Вариант 4: справочник контактов, префиксное дерево (Trie) по имени.

## Запуск

Папку `lab2` открыть в VS Code с расширением Extension Pack for Java. Нужен JDK 21 или новее.

- окно: Run and Debug, конфигурация «Окно» (или `mvn javafx:run`);
- демонстрация гонки потоков: конфигурация «RaceDemo»;
- замеры Trie и TreeMap: конфигурация «Benchmark»;
- тесты: панель Testing, Run Tests (или `mvn test`).

## Дерево

`Trie<V>` хранит в каждом узле букву, значение (если на этом узле заканчивается имя), счётчик
значений в поддереве `count` и детей. Дети лежат в двух массивах: `letters` (буквы по алфавиту)
и `children` (узлы). Нужного ребёнка ищем бинарным поиском, при добавлении массив сдвигается,
а когда место кончается, увеличивается в два раза.

Имена хранятся без учёта регистра и пробелов по краям (`Trie.normalize`). Перевод в нижний регистр
идёт с `Locale.ROOT`, чтобы результат не зависел от языка системы.

| Операция | Сложность | Почему |
|---|---|---|
| вставка `put` | O(L · log k) | спуск по L буквам имени, в каждом узле бинарный поиск среди k детей |
| поиск `get` | O(L · log k) | то же |
| удаление `remove` | O(L · log k) | спуск и подъём обратно с уменьшением счётчиков, пустые ветки удаляются |
| подсчёт в поддереве `countWithPrefix` | O(P · log k) | спуск по префиксу, ответ уже лежит в `count` |
| автодополнение `findWithPrefix` | O(P · log k + m) | спуск по префиксу, потом обход, пока не наберём m результатов |

L — длина имени, P — длина префикса, k — число детей у узла (не больше размера алфавита).

## Хранилище и потоки

`Store<T>` — интерфейс хранилища. `TrieStore<T>` реализует его на `Trie` и получает функцию,
которая достаёт ключ из объекта (`Contact::getName`), и функцию создания массива (`Contact[]::new`).
Она нужна, потому что в Java нельзя написать `new T[n]`. `ContactStore` — это `TrieStore<Contact>`
с этими двумя функциями.

- `add` бросает `DuplicateKeyException`, если имя занято;
- `update` бросает `KeyNotFoundException`, если старого имени нет, и `DuplicateKeyException`,
  если новое имя занято другим контактом.

Все методы `TrieStore` объявлены `synchronized`: пока один поток работает с деревом, остальные ждут.
`RaceDemo` запускает 8 потоков, которые пишут в голый `Trie` (часть записей теряется) и в
`TrieStore` (всё на месте). Это же проверяет `ConcurrentWriteTest`.

## Окно

- Таблица контактов. Справа дерево на `Canvas` (`TriePane`).
- Поле «Префикс» оставляет в таблице только имена с этим началом. Рядом показывается, сколько
  их в поддереве.
- Красным подсвечивается путь последней операции: поиска, добавления, удаления или выбранной строки.
- Если узлов больше 300, рисуются первые 300 по уровням, а у обрезанных узлов стоит «...».
- Загрузка CSV, сохранение и генерация выполняются в `Task` в отдельном потоке. Прогресс виден
  внизу, кнопка «Отмена» вызывает `task.cancel()`.
- CSV загружается в новое хранилище, и старое заменяется только после успешной загрузки.
  Поэтому при отмене данные не меняются.
- Изменять можно только контакты, которые реализуют `Editable` (корпоративные). Экстренные
  контакты только для чтения.
